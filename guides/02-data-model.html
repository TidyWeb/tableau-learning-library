Data model: tables that know how they fit

The Data Source page is where Tableau learns the shape of the data. This is the part that makes the three CSV files useful together.

The Retail model

Three tables, three jobs

Keys and grain

What does “linked” mean?

A relationship uses one or more common columns as matching fields. Those columns are often called a key. The key is not a magical ID stored separately; it is simply the field or combination of fields that lets Tableau find corresponding records.

TableOne row representsRelationship field
FeaturesOne store on one weekStore + Date
SalesOne store, department and weekStore + Date to Features; Store to Stores
StoresOne storeStore
Composite key: Store on its own is not enough to match Features to Sales because Store 1 appears on many dates. Store + Date identifies the weekly context.

Relationship versus join

Why Tableau does not simply merge everything

Relationship

Defines how tables fit without flattening them first. Tableau can combine the relevant fields when a worksheet needs them, while preserving each table’s level of detail.

logical model

Join

Creates a fixed combined row structure. Useful when grains genuinely match, but dangerous when a weekly context row is repeated across department-level sales.

physical merge

Union

Appends rows from tables with the same column structure. It is not the right operation for Features, Sales and Stores.

append rows

In your workbook, the blue boxes and lines on the top Data Source canvas are the logical relationship model. If you open a table and see another canvas inside it, you are looking at the physical join layer instead.

Official context: Don't Be Scared of Relationships ↗ and Plan the Data Source ↗.

Relationship settings

What the cardinality and matching options tell Tableau

SettingRetail choicePlain-English interpretation
Features ↔ Sales cardinalityMany-to-manyOne weekly Features record can relate to many department sales records, and the model should not assume a one-to-one match.
Sales ↔ Stores cardinalityMany-to-oneMany sales rows belong to one store lookup row.
Referential integritySome records match on Sales; all records match on StoresSales may contain rows without a matching lookup record, while every Stores row is expected to be represented in Sales.
Do not “fix” a relationship warning by guessing. First inspect the field names, data types, spaces, date formats and unmatched values. A warning can reveal a genuine data-quality issue.

Validation

Before you build a chart

  1. Confirm the three logical boxes are Features — Sales — Stores.
  2. Click the Features–Sales line and check Store = Store and Date = Date.
  3. Click the Sales–Stores line and check Store = Store.
  4. Check that fields appear under their original tables in the worksheet Data pane.
  5. When you eventually use a field from another table, compare a known total before and after adding it.
Success condition: the model is correct when Tableau can bring weekly Features context and store lookup information into sales analysis without unexpectedly multiplying the sales total.

Do it in Tableau

Load the three CSV files into a new workbook

This is the hands-on route that takes you from an empty Tableau Public workbook to the model described above. Start here when the workbook has no data in it yet.

1. Start on the Connect page

  1. Open Tableau Public and choose New Workbook.
  2. On the Connect page, under To a File, select Text file.
  3. Browse to the folder containing the three retail CSV files and select Features data set.csv.

Tableau now opens the Data Source page. You should see a blue logical table box for Features and a list headed Files on the left.

2. Add the other two files from the Files list

Do not look for a second connection button for this exercise. Once Features is loaded, use the Files list on the left:

  1. Drag sales data-set.csv onto the logical canvas near the Features box.
  2. When Tableau creates a relationship, set Store = Store and Date = Date.
  3. Drag stores data-set.csv onto the canvas near Sales.
  4. For that relationship, set Store = Store.
Important UI translation: the word Store in the relationship editor is a column name (a field), not the Stores table. The table is called stores data-set.csv.

3. Finish the relationship without hunting for a button

There is no separate Done, Finish or Accept button in this relationship editor. Once the correct fields appear on both sides of the equals sign, the relationship is set. Click another table or an empty part of the canvas to leave the editor, then check the line between the boxes.

4. Move from Data Source to the worksheet

  1. Click Sheet 1 at the bottom left.
  2. Tableau opens the worksheet workspace. The Data pane should contain the fields from the related tables.
  3. Only now begin dragging fields onto Rows, Columns, the Marks card or the view.
Checkpoint: stop here and confirm that the three tables are visible in the Data pane before starting Section 3. If you only see one table, return to the Data Source tab and check the logical relationships.
